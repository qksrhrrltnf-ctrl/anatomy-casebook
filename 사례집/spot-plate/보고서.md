# spot-plate 보고서

기준: `wheresryan22/anatomy` 커밋 `1482e84`, 예제 폴더 `examples/spot-plate/` (React, Fig 7 "Spot plate")

## 1. 재현 결과

- **판정 방식**: 원본 HTML 없음, 렌더 확인과 콘솔 오류로 판정합니다. 이 예제는 Next.js용 React 컴포넌트만 들어 있고 `build.mjs`도 원본 HTML도 없어서 바이트 비교를 할 수 없습니다.
- **렌더**: 다크·라이트 모두 정상으로 나옵니다. 받침판, 6개 홈이 파인 반점판(홈마다 R30·R22 유리 방울 한 쌍과 눈금자), 오른쪽 데크 위의 각도기 눈금과 필러 게이지 날 부채(날 6개 + 맨 위 merge 날), 피벗, 스포이트 병, 범례와 캡션이 모두 보입니다.
- **콘솔 오류**: 없습니다. `capture.mjs`는 console error와 warning, 잡히지 않은 예외를 모두 기록하는데, 모든 캡처(정적 빌드 http, file://, Vite 개발 서버)에서 `console: clean`이었습니다. React 개발 모드(StrictMode 포함)에서도 경고가 나오지 않았습니다.
- **가로 스크롤**: 1440px, 390px 모두 없습니다.
- **움직임**: 자동 투어가 merge 48 → 0 → 20 순서로 부채를 여닫는 것이 시간대별 판독값으로 확인됩니다(`merge 47 px · 6 of 6 joined` → `merge 4~5 px · 0~1 of 6 joined` → `merge 18~19 px · 3 of 6 joined`). 판독값의 "joined" 개수는 `gap < merge` 규칙(간격 4, 10, 16, 24, 32, 44)과 맞습니다. 예: merge 32에서 4개, merge 20에서 3개.
- **키보드**: 포커스 후 End를 누르면 `merge 48 px · 6 of 6 joined`가 됩니다(`shots/spot-plate-dark-keys.png`).
- **reduced motion**: 투어가 돌지 않고 3초 뒤에도 `merge 20 px · 3 of 6 joined` 휴지 상태로 남습니다.

### 하네스 구성 (`C:\anatomy-work\react-harness`)

test-rig와 같은 하네스를 씁니다.

- Vite 8.3.5 + `@vitejs/plugin-react` 6.2.1 + React 19.3.0 / react-dom 19.3.0 + TypeScript 5.9.3 (+ esbuild 0.28.2, `@types/react`·`@types/react-dom` 19.3.0). 버전은 저장소 CI 기준에 맞췄습니다.
- `kit/` 전체와 두 예제 폴더를 `src/kit`, `src/examples/...`로 **복사**했습니다. 상대 경로(`../../kit/...`)가 그대로 맞도록 폴더 구조를 유지했으므로 import 별칭은 쓰지 않았습니다. 복사본은 `diff -r`로 원본과 같음을 확인했습니다.
- 하네스 쪽에만 둔 코드:
  - `index.html`: `<body class="iso" data-theme="dark|light"><main class="iso-page" id="root">`. SVG 예제들의 `pageHtml()` 껍데기와 같은 구조입니다.
  - `src/harness/page.css`: `kit/iso-kit.ts`의 `PAGE_CSS`(폭 650px)를 옮겨 적었습니다.
  - `src/harness/mount.tsx`: `kit/iso.css`와 `page.css`를 import하고 `<React.StrictMode>` 안에 렌더링합니다. `?theme=light|dark` 쿼리로 테마를 바꿀 수도 있습니다.
  - `src/harness/spot-plate.tsx`: `<SpotPlateFigure />`를 마운트합니다.
  - `vite.config.ts`: 환경변수(`HARNESS_FIG`, `HARNESS_THEME`)로 그림과 테마를 고르고, `vite-plugin-singlefile` 2.3.4로 JS·CSS를 인라인합니다. `resolve.extensions`를 `.tsx, .ts`가 먼저 오도록 바꿨습니다. `kit/`에 `iso-kit.ts`와 `iso-kit.mjs`가 함께 있는데, Vite 기본 순서는 `.mjs`가 먼저라서 React 키트가 기준으로 삼는 `iso-kit.ts`를 고르게 하려는 것입니다.
  - `build-all.mjs`: 4번(그림 2 × 테마 2) 빌드해 `dist/<이름>.html`, `dist/<이름>-light.html`을 만듭니다.
- Next.js 전용 구분(`"use client"`, 서버 컴포넌트인 `art.tsx`)은 그대로 두고 전부 클라이언트에서 렌더링했습니다.
- `tsc --noEmit`(strict) 통과했습니다.

## 2. 무엇을 설명하는 그림인가

컴퓨터 그래픽스의 "거리장(distance field)과 부드러운 합집합(smooth union)", 흔히 메타볼·리퀴드 글래스 효과에서 두 방울이 가까워지면 하나로 이어지는 현상을 실험실 반점판(spot plate)으로 보여 줍니다. 홈 6개에는 반지름 30과 22인 유리 방울 쌍이 4, 10, 16, 24, 32, 44px 간격으로 놓여 있습니다. 각 쌍은 하나의 거리장으로 그려지므로 간격이 merge 값보다 작으면 목(neck)이 생기며 한 덩어리가 됩니다. 오른쪽의 필러 게이지(틈새 게이지) 부채가 merge 값을 정합니다. 날마다 자기 간격에서 멈추므로, 펼쳐진 날의 수가 합쳐진 쌍의 수와 같습니다. 간격이 merge보다 크지만 2배보다 작으면 방울이 서로를 향해 늘어나는 모습도 보입니다(merge 32에서 간격 44 쌍).

## 3. 조작법

- **마우스**: 그림 위에서 가로로 움직이면 merge가 바뀝니다(그림 폭 16%~84% 구간이 0~48px에 대응). 마우스가 그림을 벗어나면 merge 20으로 천천히 돌아갑니다.
- **터치**: 누른 채 가로로 끌면 같은 방식으로 바뀝니다.
- **키보드**: 그림에 포커스를 두고 ←→(↑↓)로 1px(Shift는 4px), PageUp/PageDown으로 8px, Home/End로 0/48px.
- **자동 투어**: 화면에 보이고 조작이 없으면 1.8초 뒤부터 48 → 0 → 20을 돕니다. 조작 후 4.2초가 지나면 다시 시작합니다. reduced motion에서는 돌지 않습니다.

## 4. 눈여겨볼 기법

- **거리장 → 등고선 → 입체**: `rig.ts`의 `fieldOf`가 두 원의 부호 거리를 부드럽게 합치고, `drops.ts`가 격자에서 값을 뽑아 마칭 스퀘어(16가지 경우 표)로 0 등고선을 찾은 뒤 단순화해 두께 있는 유리 입체로 세웁니다. 가려지는 옆면 구간 계산, 오목한 부분 처리, 반짝임(glint)도 직접 계산합니다. 수식으로 정의한 모양을 아이소메트릭 입체로 만드는 방법으로 2단계에서 참고할 만합니다.
- **캐시**: `keyOf(merge)`로 0.25px 단위 키를 만들어 같은 merge의 모양을 다시 계산하지 않게 합니다.
- **부채(fan.ts)**: 날마다 두께(`thicknessOf(gap)`)와 높이를 쌓아 올리고, 각도는 `angleOf(merge)`로 정합니다. 날마다 멈추는 각도가 그 간격에 해당하므로 그림 자체가 눈금 역할을 합니다.
- **React 구조**: test-rig와 같이 `art.tsx`(정적) + `live.tsx`(`"use client"`, ref로 직접 갱신) + `figure.tsx`(`Plate`)로 나뉩니다. 캡션 문장(`joinedListOf`, `bladesOutOf`)과 스크린리더 문장(`spokenOf`)도 모델에서 계산합니다.
- lathe, tube, WebGL, 3D, 분해, 인쇄는 쓰지 않습니다.

## 5. 교육 활용 메모

- 중학교 과학 "물질의 상태"·고등학교 화학의 표면장력·응집력 단원에서, 가까운 물방울이 붙어 하나가 되는 현상을 "어느 거리부터 합쳐지는가"라는 문턱값으로 보여 주는 보조 자료로 쓸 수 있습니다. 다만 그림의 합쳐짐은 실제 물리 계산이 아니라 그래픽 기법이라는 점을 함께 알려야 합니다.
- 고등학교 정보·수학(함수와 그래프, 등고선)에서 "거리 함수의 등고선이 모양을 만든다"는 개념과, 기술 교과의 측정 단원에서 틈새 게이지 사용법을 설명하는 데 쓸 수 있습니다.

## 6. 문제와 미해결 사항

- 원본 HTML이 없어 바이트 비교는 하지 않았습니다. 원저자의 실서비스(Next.js) 화면과 픽셀 대조도 하지 않았습니다.
- 하네스는 전부 클라이언트 렌더링이라 `references/react.md`가 말하는 "큰 페이지의 서버 스트리밍 key 경고 함정"은 이 환경에서 재현되지 않습니다. 확인한 것은 클라이언트 렌더링에서 경고가 없다는 사실까지입니다.
- 390px 폭에서는 카드 아래쪽 힌트("SLIDE ACROSS TO OPEN THE FAN")와 판독값이 한 줄에 들어가지 않아 두 줄로 나뉩니다. 겹치거나 잘리지는 않습니다.
- 캡션 문장은 휴지 상태(merge 20)를 기준으로 고정되어 있어, 조작 중에는 판독값과 캡션 숫자가 다를 수 있습니다. 원본 코드가 그렇게 짜여 있습니다.
- Windows에서 캡처했으므로 글꼴은 `iso.css` 글꼴 목록 가운데 Windows에 있는 글꼴로 표시됩니다.
- 직접 본 캡처(데스크톱 다크·라이트, 투어 세 순간, 호버, 390px, reduced, 확대)에서 부품이 빠지거나 앞뒤 겹침이 틀린 곳은 찾지 못했습니다. 방울은 홈 안에 그려지고, merge 48의 확대 화면에서 날 끝은 각도기 띠 안쪽에서 멈춥니다.
