## 2. 무엇을 설명하는 그림인가

시험대(test stand)에 거꾸로 매달린 **SpaceX Raptor 2 로켓엔진**입니다. 다른 Anatomy 예제처럼 추상 개념을 비유한 그림이 아니라, 실물 엔진 자체의 작동 원리(full-flow staged combustion, 전유량 다단 연소)를 보여 줍니다.

- 액체산소(−183 °C)와 메탄(−162 °C)을 각각의 터보펌프가 300 bar까지 올립니다.
- 산소는 전부 산소 과잉 예연소기(oxygen-rich preburner)를 지나며 산소 펌프 터빈을 돌리고, 메탄은 전부 연료 과잉 예연소기를 지나며 메탄 펌프 터빈을 돌립니다.
- 두 뜨거운 가스가 주연소실에서 만나 300 bar로 탑니다. 이미 뜨거운 상태로 만나므로 주연소실에는 점화기가 없습니다.
- 메탄은 타기 전에 다운커머로 내려가 노즐 벽을 지나며 노즐을 식힙니다.
- 노즐 출구 1.3 m, 해수면 추력 230 tf, 건조 질량 1,630 kg, 혼합비 3.6:1입니다.

엔진은 11개 묶음(assembly)으로 나뉩니다. 01 짐벌과 추력 퍽, 02 산소 터보펌프, 03 산소 과잉 예연소기, 04 산소 덕트와 주밸브, 05 엔진 제어기와 배선, 06 분사기와 주연소실, 07 고온가스 매니폴드, 08 메탄 터보펌프와 연료 과잉 예연소기, 09 다운커머와 주연료밸브, 10 배관, 11 노즐입니다. (근거: `build.mjs`의 `PIECES`·캡션, `sheet.mjs`의 `parts`·`steps`)

## 3. 조작법

`live.js`의 이벤트 처리 코드와 실제 캡처에서 확인한 내용입니다.

| 입력 | 동작 |
|---|---|
| 엔진 위에 마우스 올리기 | 엔진이 11개 묶음으로 벌어지고, 포인터 아래 부품이 강조됩니다. 오른쪽 아래 표시창에 부품 설명이 나옵니다(예: `main chamber · 300 bar · no igniter`). 마우스가 나가면 0.26초 뒤 다시 조립됩니다 |
| 터치(휴대폰) | 부품을 누르면 분해 후 그 부품을 선택합니다. 빈 곳이나 스탠드를 누르면 분해/조립을 전환합니다. 좁은 화면에서는 안내 문구가 "Tap to take apart"로 바뀝니다 |
| `Space` | 분해/조립 전환 |
| `→` `↓` / `←` `↑` / `Home` / `End` | 부품을 01→11 순서로 하나씩 선택합니다(자동으로 분해됩니다) |
| `I` 또는 `Enter`, **Ignite** 버튼 | 점화합니다. 연소 중에 다시 누르면 정지합니다(버튼 이름이 "Shut down"으로 바뀝니다) |
| `Esc` | 연소 중이면 정지하고, 선택을 풀고 다시 조립합니다 |
| 범례의 부품 버튼(01~11) | 올리거나 초점을 주거나 누르면 해당 부품을 분해 상태에서 보여 줍니다 |
| 카드 오른쪽 위 **PDF** | 같은 폴더의 `raptor-engine-poster-a4.pdf`를 엽니다 |

**점화 순서**(표시창 문구): `closing up · arming`(조립) → `chill-down · venting`(0~0.7초, 회색 증기) → `spin-up · preburners lit · N bar`(0.7~1.25초) → `Pc N bar · N tf`(주연소, 약 300 bar · 230 tf까지 상승) → `shutdown · N bar` → `shutdown · purging`. 직접 점화하면 주연소 시작 후 약 9초 뒤 스스로 정지합니다.

**자동 투어**: 페이지를 열면 0.4초 뒤 분해되고, 11개 부품을 1.5초씩 차례로 강조한 다음, 다시 조립하고 약 4초간 점화합니다. 사용자가 조작하면 멈추고, 마지막 조작 3.6초 뒤 다시 시작합니다.

**움직임 줄이기(reduced motion)**: 투어가 꺼지고 정지 화면으로 시작합니다(`light-reduced.png`).

**WebGL이 없을 때**: 화염 셰이더 대신 노즐 끝 테두리 빛(rim light)과 CSS 바닥 빛만 나옵니다. 엔진 그림과 조작은 그대로입니다(`*-nowebgl-firing.png`).

## 4. 눈여겨볼 기법

- **lathe(회전체)**: 노즐 종, 연소실, 펌프 하우징, 플랜지처럼 둥근 부품은 모두 `kit/lathe.mjs`로 단면 프로파일을 돌려 만듭니다. 노즐 곡면의 매끄러운 명암이 참고할 만합니다.
- **tube(관·배선)**: 덕트, 감지관, 퍼지 라인, 제어기 배선 80개를 `kit/tube.mjs`로 그립니다. 조밀한 배관을 그리는 기준 예제입니다(SKILL.md).
- **분해**: 11개 묶음이 시차(stagger 0.035초)를 둔 스프링으로 벌어지고, 매 프레임 깊이 순서를 다시 정렬합니다. 분해 중에도 관이 다른 부품을 뚫지 않는다는 것을 감사가 증명합니다.
- **기하 감사**: `kit/audit.mjs`가 조립·분해·중간 프레임 1,119개 상태에서 관통, 지지, 끝점, 깊이 순서를 검사합니다. 2단계에서 복잡한 기계를 그릴 때 그대로 따라 할 검증 방식입니다.
- **WebGL**: 뒤 SVG와 앞 SVG 사이에 캔버스를 두고, 그림과 같은 등각 카메라로 화염, 마하 디스크(충격파 고리), 바닥 튀김, 증기를 그립니다. 기둥과 바닥 원뿔은 셰이더 안에서 가림체로 모델링되어 화염이 그림 속에 들어가 있는 것처럼 보입니다(`references/webgl.md` "Worked case: the Raptor").
- **표시창 모델**: 연소실 압력과 추력 숫자가 같은 연소 모델에서 나옵니다(300 bar → 230 tf).
- **인쇄**: `sheet.mjs` 하나로 포스터, 도면, 상세 해설 3종 A4 PDF를 만듭니다. 분해 자세를 벡터로 고정하고 화염만 2배 PNG로 넣습니다.
- 2단계 참고: 펌프·밸브·배관이 많은 장치(열기관, 냉동기, 수력발전 터빈 등)는 이 예제의 lathe + tube + 분해 + 감사 조합을 그대로 본뜰 수 있습니다.

## 5. 교육 활용 메모

- **중학교 과학(힘과 운동)·고등학교 물리학**: 노즐에서 가스를 아래로 내뿜는 힘과 엔진이 위로 받는 230 tf 추력으로 작용·반작용을 설명할 수 있습니다. 점화 단계마다 압력과 추력 숫자가 함께 오르는 것도 보여 줄 수 있습니다.
- **화학(연소·산화 반응)**: 메탄과 산소의 연소, 산소 과잉/연료 과잉 예연소, 극저온 액체 추진제를 다룰 때 쓸 수 있습니다.
- **기술·가정(기계와 에너지 변환, 수송 기술)**: 11개 부품을 하나씩 분해·조립하며 펌프-터빈-연소실-노즐로 이어지는 에너지 흐름과 기계 구조를 보여 줄 수 있습니다. 인쇄용 상세 해설 PDF는 활동지로 바로 쓸 수 있습니다.

모든 문구가 영어이므로, 수업에 쓰려면 한국어 설명을 따로 곁들여야 합니다.

## 6. 문제와 미해결 사항

1. **HTML이 원본과 바이트 단위로 같지 않습니다.** 위 1절의 4개 숫자, 마지막 자릿수만 다릅니다. Node 버전 차이로 추정하며, Node 22로 다시 빌드해 확인하지는 않았습니다.
2. **라이트 테마 화염 색**: 라이트에서 화염이 붉은 잉크 연기처럼 보입니다. 원본 `raptor-engine-firing.webp`도 같으므로 재현 문제는 아닙니다. `references/webgl.md`도 이 화염(`inkOf`)을 "red ink smoke"라는 리뷰를 받은 사례로 들며 따라 하지 말라고 적고 있습니다.
3. **캡처의 안쪽 둥근 테두리**: drive.mjs로 키를 누른 캡처에는 무대(`.rp-stage`)에 초점 테두리가 보입니다. 키 입력 때문에 생긴 것이며, 키를 누르지 않은 `*-reduced.png`, `*-capture-default.png`에는 없습니다.
4. **원본 홍보 이미지와의 차이**: `.github/assets/raptor-engine-apart.webp`와 `raptor-engine-firing.webp`는 라이트 테마 장면입니다. `light-apart-otp.png`(산소 터보펌프 선택), `light-fire5-pc300.png`(`Pc 300 bar · 230 tf`)가 같은 장면입니다. 현재 빌드는 카드 오른쪽 위에 PDF 버튼이 있고 홍보 이미지에는 없습니다. 이미지가 PDF 기능보다 먼저 만들어졌기 때문으로 보입니다.
5. **캡처 요령**: 다른 작업으로 CPU가 바쁘면 분해 스프링이 멈추기 전에 3.6초 자동 투어가 다시 시작해, 표시창이 `apart · 11 assemblies`에 이르지 못합니다. `verify.md`가 권하는 대로 `--preload`로 3600 ms 타이머를 막아 해결했습니다(`setTimeout` 대체 스크립트).
6. **저장소 작업 트리 상태**: 재빌드한 HTML 2개와 다시 만든 PDF 3개가 `git status`에 수정됨으로 남아 있습니다(PDF는 생성 시각 때문에 바이트가 다릅니다). 되돌리지 않았습니다. 인쇄 과정에서 생긴 `*-a4.html`, `*-a4.png`는 `.gitignore` 대상입니다. 다른 에이전트 몫인 `examples/turning-dial/turning-stress-light.html`도 수정됨으로 보이지만 이 작업과는 관계없습니다.
